# Weavien 帮助手册｜AI 提示词与写作工作流

> 适用于 Weavien Preview 3 的本地 GGUF AI 写作辅助。文中的模板可复制并保存为作者自己的提示词。作者拥有最终决定权；AI 输出必须经预览确认才进入 Markdown Source。

## 1. 三分钟入门

1. **确定任务**：普通写作、公文写作、知识整理；不要把“润色”“扩写”“措施建议”混为一谈。
2. **确定范围**：选区只处理选中文字；全文任务才允许处理全文；续写只输出新内容。
3. **确定权限**：让 AI *忠实改写*，还是允许 AI *提出新建议*？两者必须分开。
4. **检查结果**：看有无复述未选中内容、编造政策、擅改编号、增加无关标题、重复段落。
5. **作者确认**：AI 生成仅是候选内容，确认后再应用；重要公文仍须人工核实事实和依据。

**最短提示词公式**：`任务 + 目标 + 不可改变的事实/结构 + 允许新增的程度 + 输出格式`。

> 提示词不是权限系统：编辑目标位置、文档版本、修改确认等必须由 Weavien 程序保证。提示词只能提高模型遵循概率，不能替代程序校验。

## 2. 为什么同一个模型有时写得好，有时写得离题？

常见原因不只是模型大小：

- **任务含混**：“请扩写”可能被理解为补充新措施、继续整篇文章或写解释性评论。
- **目标与参考混淆**：附近正文是背景，不是要输出或替换的内容。
- **要求相互冲突**：“尽可能详细”与“保持原有篇幅”不宜同时使用。
- **输出预算过大**：一个几十字选区不应无约束生成几千字。
- **模板过长**：小模型通常更适合简短、单一、清楚的指令。

**先换提示词，再考虑换模型**。测试时固定原文、任务、模型设置和输出范围，仅改变一个变量。

## 3. Weavien 的任务边界

| 任务 | 可做 | 不可做 | 建议应用方式 |
|---|---|---|---|
| 润色/正式改写 | 改进措辞、句式、衔接 | 新增事实、制度、任务 | 替换选区 |
| 纠错 | 修正确定的字词、标点、语病 | 借机重写、增删要点 | 替换选区 |
| 忠实扩写 | 细化已有意思、补足必要衔接 | 发明新事实、措施、编号 | 替换选区 |
| 续写 | 沿已知内容继续生成**新段落** | 复述前文、重写已选内容 | 插入 |
| 精简 | 去掉重复、空话和冗长句 | 删掉实质要求、数据、限制条件 | 替换选区 |
| 摘要/提纲 | 提炼与组织已有材料 | 把推测当作事实 | 参考内容 |
| 措施建议 | 提出备选思路并标注待核实 | 冒充已批准的政策或决定 | 参考内容 |

### 3.1 目标与上下文的标准写法

复制模板时，`{target}` 表示本次**唯一处理对象**，`{context}` 表示**只读参考**，`{instruction}` 表示作者补充要求。这是手册示例占位符；只有在 Weavien 模板编辑器实际支持相应变量时才会自动替换，其他场景请手动替换，避免把占位符原样发给模型。

```text
任务：只处理 <TARGET> 中的内容。
<CONTEXT> 仅用于理解，不得复述、改写或输出未选中段落。
保持原有层级、编号和段落顺序。
只输出任务结果，不附加“修改如下”、分析或解释。

<CONTEXT>
{context}
</CONTEXT>
<TARGET>
{target}
</TARGET>
```

**重要**：如果做选区润色、纠错等局部任务，原则上只传选区；背景确有必要时才附少量上下文。敏感或无关资料不要默认送入 AI。

## 4. 普通写作：五套标准提示词

### 4.1 自然扩写（忠实原文）

```text
请自然扩写以下文字，丰富动作、场景细节和句子衔接；保持作者的叙述视角与语气。
只扩写指定文字，不复述前后文；不新增人物、关键情节、引语和未经提供的事实。
不要写文化分析、意义升华、章节标题或列表。
长度以原文字数约 1.5～2.5 倍为参考，不为凑字数重复。只输出正文。
待处理文字：
{target}
```

### 4.2 润色 / 正式改写

```text
只润色指定文字，使中文准确、自然、通顺；保持原意、人物、事实、叙述视角和段落结构。
不增加事件、结论、章节、列表，也不复述未选中的上下文。
篇幅与原文大致相当。只输出修改后的正文。
待处理文字：
{target}
```

### 4.3 纠错

```text
只纠正明确的错别字、标点、搭配和语病；不改变事实、逻辑和写作风格。
不做额外润色，不擅改专有名词。对无法确定的内容保持原样。
保留原有 Markdown 结构，只输出校正后的文字。
待处理文字：
{target}
```

### 4.4 续写（输出新内容）

```text
从所给正文的结尾继续写下一段，不重述、不改写、不引用已经给出的正文。
延续原有人物、时序、语气和叙事视角，不突然引入无依据的关键事件。
输出仅包含新增文字，不增加无关标题、注释或“续写如下”。
已有正文（只供衔接）：
{target}
```

### 4.5 精简

```text
在保留全部事实、限定条件和关键信息的前提下，删去重复、空话和多余修饰。
保持原有层级与语气，不增加新事实，不复述上下文。
只输出精简后的正文。
待处理文字：
{target}
```

## 5. 公文写作：先区分“写得规范”和“替作者定政策”

**公文润色与忠实扩写不能新增实质要求**。行政职责、处罚措施、备案、验收、联合执法、考核、信用管理、设备配置、期限等，都可能涉及权限或法律依据；未经作者提供，不应当由模型直接写成确定性要求。

### 5.1 公文起草（有材料才有事实）

```text
根据作者提供的文种、受文对象、写作目的及事实材料，拟写一份中文公文草稿。
语言准确、庄重、平实、简洁；围绕现有事实组织结构和工作要求。
不得编造机关、政策文件、数据、会议决定、法定权限、时间节点或执行情况。
必要信息缺失时标记【待补充】，不要猜测。只输出公文草稿。
文种与目的：{instruction}
已知事实材料：
{target}
```

### 5.2 公文润色（默认最保守）

```text
只将指定公文文字润色为准确、简洁、规范的书面语。
原有事实、责任主体、政策含义、工作要求、时间、数据、编号及层级一律保留。
不新增任务、制度、监管措施和程序；不将“加强”改为“杜绝”等绝对化承诺。
不输出附近原文，不增加标题与项目符号，只输出润色后的选区文字。
待润色文字：
{target}
```

### 5.3 公文忠实扩写（默认扩写模式）

```text
请适度展开指定公文文字，使原有工作要求更加清楚、衔接更自然。
只能细化原文已明确的事项；不得新增工作任务、考核制度、执法权限、监管程序、技术标准、报告或验收要求。
保持原有标题、编号、层级和顺序，包括看似不连续的编号，不得擅自补项。
用语庄重、平实，避免“全面深入”“必须严格”“有效确保”等空泛叠加。
长度一般不超过原文的两倍，必要时宁可短些。仅输出扩写后的指定文字。
待扩写文字：
{target}
```

### 5.4 公文续写（仅新增段落）

```text
根据已有公文的主题、文种和结构继续起草后续段落。
仅输出新写内容，不重写、复述已有段落；尊重已有编号逻辑。
已确定的事实和工作要求可以延续，缺少依据的新政策、权责或数据不得编造。
如需补充具体单位、时间或数据，用【待补充】标识。
已有公文（只供衔接）：
{target}
```

### 5.5 公文精简

```text
压缩下列公文文字，删除重复、套话和冗长修饰。
不得删去责任主体、执行要求、期限、条件、依据和关键事实，不改变措辞的法律或政策含义。
保持原编号与 Markdown 段落结构，只输出精简后的文字。
待处理文字：
{target}
```

### 5.6 措施建议（独立任务，不能自动写回正文）

```text
请围绕以下工作目标提出若干备选措施，作为作者讨论和核实的参考。
区分“材料已明确的要求”和“AI 提出的建议”；不得把建议写成既有政策、已批准的任务或法定义务。
涉及法律依据、职责、检查、处罚、备案、验收、指标的建议，标注【需核实依据及适用范围】。
输出：建议事项 / 适用前提 / 需要核实的信息。不要直接改写原文。
工作目标和已知材料：
{target}
```

### 5.7 公文审核（出建议，不直接替换）

```text
检查以下公文中的错字、语病、重复、序号、逻辑不一致及疑似缺失要素。
按“原文位置—问题—修改建议—理由”列出；将政策依据、职责权限、数据、时点等无法凭文本确定的问题标为【人工核实】。
无问题处不重复输出；不要直接改写全文或擅自替换 Source。
待审核文字：
{target}
```

> **公文排版另有职责**：GB/T 9704—2012 涉及的版式、字体与页面设置，应由 Weavien 的公文模板、预览和导出流程落实；AI 语言提示词不能保证 DOCX 版式合规。

## 6. 知识整理：不要把推断包装成原文事实

### 6.1 摘要

```text
用简洁中文总结材料的主要事实、核心观点、关键结论。
仅使用所给材料；不补充外部资料，不把推断写成事实。
分成“核心摘要”和“待核实信息”两部分；未发现待核实内容可省略该部分。
材料：
{target}
```

### 6.2 提取要点与提纲

```text
依据材料生成层级清晰的要点提纲，保留原文的重要限定条件、数字和不同观点。
不虚构材料未涉及的章节、结论或关联。不能确定的主题以“可能”标注。
仅输出提纲。
材料：
{target}
```

### 6.3 多笔记整理（需要作者明确提供材料）

```text
整理下列多份笔记，分别提取共同主题、差异和可追溯的依据。
每条判断注明来自哪份笔记；区分“笔记原文”“综合推断”“后续问题”。
不得虚构引用或引用未提供的文件。输出供作者审核的整理建议，不修改原笔记。
笔记材料：
{target}
```

## 7. 针对不同模型的实际使用方法

你可以用 Weavien 支持的 GGUF 模型对比中文写作，但不要简单假定更大、更新的模型就一定适合公文。

- **Gemma 4 E2B**：优先用短指令、明确目标，控制输出长度；观察是否出现概括性评论或冗长解释。
- **Qwen3.5 4B**：适合测试中文公文措辞与措施建议，但重点检查是否擅自新增监管机制、具体政策要求和编号。
- **Mistral 小模型**：测试结构、摘要和备选思路；尤其检查是否扩成多层清单，或改变原文格式。

这些只是基于现有试写样本的经验观察，不代表对所有模型版本的定论。

**统一的测试方法**：使用同一段原文、同一个模板、相同的任务范围和可比较的推理参数，记录“内容质量、事实忠实、结构保留、越界复述、生成耗时”。

## 8. 示例：环保公文为什么不宜随意增加措施？

**原文**：

> 加强物料储存、运输、装卸等环节管理，严禁违法违规排放污染物。对发现的问题要及时整改并报告整改情况。

**忠实扩写（可作为草稿）**：

> 加强物料储存、运输、装卸等环节的日常管理，规范相关作业行为，严禁违法违规排放污染物。对管理中发现的问题，应及时采取整改措施，并按要求报告整改情况，推动问题及时解决。

**不应由“忠实扩写”擅自加入**：联合执法、信用惩戒、第三方验收、专项备案、具体监测设备、强制处罚、考核办法等。若作者确有需要，应转入“措施建议”模板，再核实适用依据后决定是否采用。

**关于编号**：原文若从“（1）”直接到“（3）”，润色和忠实扩写应保留原编号；由单独的“公文审核”提示作者检查是否漏项。

## 9. 常见故障与处理

| 现象 | 先检查 | 建议处理 |
|---|---|---|
| 选中几十字却输出整章 | 任务范围、上下文、输出上限 | 只传选区；缩短生成预算；检查重复原文并拒绝异常替换 |
| 续写重新打印前文 | 是否把参考内容当目标 | 明确“只输出新增内容”；必要时降低上下文和输出预算 |
| 公文新增制度、处罚、验收 | 是否用了“措施建议式”指令 | 改用“公文润色”或“忠实扩写”，核查每项新增要求 |
| 文字过度啰嗦 | 扩写倍数和“尽可能详细” | 要求平实简洁，降低扩写倍数，删去空泛套话 |
| 自动补编号、改标题 | 模板是否允许重组结构 | 明确保留原结构；需调编号时另用审核任务 |
| 输出分析与正文混杂 | 输出格式不清楚 | 指定“仅输出正文”；异常输出不要直接应用 |
| 整段重复 | 模型续生成或前端拼接都可能 | 先检查原始响应和界面流；不要仅凭粘贴内容断言是引擎故障 |

## 10. 保存自己的模板

建议将系统默认模板保留为基准，再“复制/另存”为作者自定义模板，并给它一个描述明确的名字，例如 `公文·忠实扩写·短版`、`随笔·自然润色`。

定制时按顺序修改：①任务目标；②允许新增内容的程度；③原文结构限制；④输出长度；⑤输出格式。**每次只改一两项**，用固定样本比较效果。

如果当前版本的界面没有提供某项变量、分类或保存操作，请使用现有的模板编辑功能或直接复制文本，不必假设界面已经支持本手册示例中的所有操作。

## 11. 发布前的快速验收清单

- [ ] 52 字选区润色：不输出其他章节。
- [ ] 52 字选区扩写：不新增标题和关键事实，篇幅合理。
- [ ] 续写：仅有新内容，不复制前文。
- [ ] 公文润色：保持政策含义、数据、编号、责任主体。
- [ ] 公文忠实扩写：不擅自创建联合执法、验收等要求。
- [ ] 公文措施建议：明确标示建议及需核实内容，不直接写入 Source。
- [ ] 摘要整理：事实可追溯，不虚构引用。
- [ ] 异常生成：能取消，且不会绕过作者确认修改原文。
